01 — The Problem

Accuracy is the wrong scoreboard.

Fraud makes up roughly 0.17% of transactions in this dataset — close to the real-world rate banks actually see. A model that predicts “not fraud” on every single transaction still scores 99.8% accuracy while catching exactly zero fraud.

So the real task isn't “build an accurate classifier.” It's: rank rare, expensive events correctly inside an ocean of normal ones, without burying a fraud team in false alarms.

02 — The Approach

Six decisions, in order.

  1. 01

    Feature engineering

    Rolling amount z-scores, time-since-last-transaction, and trailing-hour transaction counts layered on top of the anonymized PCA features — proxies for the spending-velocity signals a real card network would have.

  2. 02

    Imbalance handling

    scale_pos_weight instead of synthetic oversampling. At 280K+ rows, reweighting the loss scales cleanly; SMOTE-style resampling doesn't.

  3. 03

    Model ensemble

    LightGBM, XGBoost, and CatBoost trained independently and blended, plus an Isolation Forest trained only on legitimate transactions to catch fraud patterns no label has seen yet.

  4. 04

    Calibration

    Isotonic regression on held-out validation data, so a score of 0.80 means an 80% real-world likelihood — not just a high rank.

  5. 05

    Cost-based thresholding

    The cutoff is chosen by minimizing expected dollar cost (missed fraud vs. false-alarm investigation time) — not by maximizing F1 for its own sake.

  6. 06

    Explainability

    SHAP values attached to every flagged transaction, so each decision comes with a reason, not just a number.
